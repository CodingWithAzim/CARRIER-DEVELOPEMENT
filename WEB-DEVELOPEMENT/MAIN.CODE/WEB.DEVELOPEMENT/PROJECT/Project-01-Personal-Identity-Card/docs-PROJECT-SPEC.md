# Project 01 — Personal Identity Card

## 1. Project Name
Personal Identity Card

## 2. Difficulty
1/10

## 3. Learning Value
5/10

## 4. Design Challenge
3/10

## 5. Technical Challenge
2/10

## 6. Project Goal
Build a small personal identity interface that communicates who you are, what you are learning, and how someone can contact you.

## 7. Why This Project Comes NOW
This is the first project. It establishes semantic HTML, basic visual hierarchy, spacing, typography, and a simple responsive composition before more complex layouts are introduced.

## 8. Previous Skills Being Reused
None. This is the baseline project.

## 9. NEW Skills Being Introduced
Semantic HTML, CSS custom properties, basic Flexbox/Grid, responsive thinking, hover states, focus-visible states, and basic accessibility considerations.

## 10. Required Features
- Name and role
- Short introduction
- Three current skills
- Availability/status indicator
- Location
- Contact link

## 11. Required Sections/Pages
One page with header, introduction, skills, and footer.

## 12. UI/UX Requirements
Make the identity easy to scan in a few seconds. Establish clear hierarchy between name, role, description, skills, and contact action.

## 13. Design Direction
Modern editorial/digital identity card. Use deliberate whitespace, restrained decoration, strong typography, and a distinctive accent rather than a generic template.

## 14. Responsive Requirements
The layout must remain comfortable on mobile, tablet, and desktop. No horizontal scrolling.

## 15. Interaction Requirements
At minimum, provide a useful hover treatment and a visible keyboard focus state for the contact link.

## 16. Accessibility Requirements
Use semantic elements, logical heading hierarchy, descriptive link text, visible focus styles, sufficient contrast, and reduced-motion consideration.

## 17. Performance Considerations
Keep the page lightweight. Avoid unnecessary JavaScript and heavy libraries.

## 18. Edge Cases
Long names, long job titles, narrow mobile screens, zoomed text, and keyboard navigation should not break the layout.

## 19. Constraints
HTML + CSS only. No JavaScript framework. No UI library.

## 20. Things I Should Figure Out Myself
How to choose the exact spacing scale, font sizes, border radius, card composition, responsive breakpoint, accent color, and final visual identity.

## 21. Acceptance Criteria
The page loads without errors, looks intentional, is readable on mobile and desktop, has no horizontal overflow, includes visible focus styling, and communicates the identity clearly.

## 22. Skills I Should Be Able To Demonstrate After Finishing
I should be able to structure a semantic HTML page, style it with modern CSS, create a responsive composition, and explain why I chose my basic layout and visual hierarchy.
