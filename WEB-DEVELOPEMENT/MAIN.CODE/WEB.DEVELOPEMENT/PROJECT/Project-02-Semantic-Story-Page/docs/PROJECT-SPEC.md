# Project 02 — Semantic Story Page

## 1. Project Name
Semantic Story Page

## 2. Difficulty
2/10

## 3. Learning Value
6/10

## 4. Design Challenge
4/10

## 5. Technical Challenge
3/10

## 6. Project Goal
Build a modern editorial-style article page that tells one short story while practicing semantic HTML and a clear reading hierarchy.

## 7. Why This Project Comes NOW
Project 01 introduced a compact component-like card. Project 02 deliberately moves into long-form content so you learn document structure, readability, sections, and hierarchy instead of repeating card UI.

## 8. Previous Skills Being Reused
Basic HTML structure, headings, paragraphs, links, CSS typography, spacing, box model, basic responsive thinking.

## 9. NEW Skills Being Introduced
Semantic HTML, article structure, figure/figcaption, blockquote/cite, time/address elements, accessible navigation, sticky positioning, editorial layout, reduced-motion preference.

## 10. Required Features
- Branded header and navigation
- Large editorial headline
- Story metadata
- Hero image with caption
- Main article divided into semantic sections
- In-page section navigation
- At least one quotation
- At least one highlighted fact or callout
- Footer

## 11. Required Sections/Pages
Single page with:
- Header
- Story introduction
- Hero figure
- Story navigation
- Three content sections
- Quote/callout areas
- Footer

## 12. UI/UX Requirements
Prioritize reading comfort, obvious hierarchy, sensible line length, strong contrast, meaningful spacing, and easy section navigation.

## 13. Design Direction
Modern independent editorial publication. Avoid generic blog templates. Use typography and whitespace as the primary visual tools.

## 14. Responsive Requirements
The page must remain readable on mobile, tablet, and desktop. The side section index should transform into a normal block on smaller screens.

## 15. Interaction Requirements
Navigation links should move to the correct sections. Keyboard users must be able to reach all links.

## 16. Accessibility Requirements
Use semantic elements, descriptive image alt text, visible focus states, a skip link, correct heading hierarchy, meaningful link labels, and reduced-motion support.

## 17. Performance Considerations
Keep assets lightweight. Avoid unnecessary JavaScript and external dependencies beyond the chosen font. Use responsive image dimensions/aspect ratios sensibly.

## 18. Edge Cases
Very long headline, very long navigation labels, narrow mobile screens, missing image, disabled animation preferences.

## 19. Constraints
HTML + CSS only for the main implementation. No JavaScript framework. No UI library.

## 20. Things I Should Figure Out Myself
Exact spacing scale, font pairing, color palette, article width, breakpoint values, how the side navigation behaves, and the visual treatment of callouts.

## 21. Acceptance Criteria
- Valid, semantic HTML structure
- No unnecessary div-only page structure
- Responsive from small mobile to desktop
- Readable article line length
- Accessible keyboard focus
- Image has useful alternative text
- Navigation jumps to the intended sections
- Visual hierarchy is obvious without explanation

## 22. Skills I Should Be Able To Demonstrate After Finishing
You should be able to structure a long-form webpage semantically, create an editorial layout with CSS, design responsive transformations, and explain why you chose specific HTML elements and visual hierarchy decisions.
